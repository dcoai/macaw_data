# 00 — Overview {#data-overview}

## 1. What macaw_data holds {#data-holds}

`macaw_data` is the smallest Macaw package, and the one every other depends on for data ([macaw_compose 00 §4](https://github.com/dcoai/macaw/blob/main/spec/00-overview.md#overview-packaging)):
- **the interaction event** and its recorded form ([01 §8](01-sources.md#sources-event));
- **the data model:** Table, Schema, Delivery, units, quantities and facts ([01 §1](01-sources.md#sources-data), [03](03-units.md)), and the formats a value is written in ([05](05-format.md));
- **the source contract,** push, change notification and the source conformance kit ([01 §2–§7](01-sources.md#sources-contract), [§9](01-sources.md#sources-conformance));
- **derived sources** ([02](02-derived.md)), and **the operations** they and designs share: the transform and aggregate behaviors, the registry of enabled packages, the table operations and the statistics ([04](04-operations.md)).

It knows nothing of pages, components or state: those are `macaw_compose`'s, which depends on it. A derived source takes its inputs as named sources ([02 §2](02-derived.md#derived-inputs)); that state sources and exports satisfy the source contract is `macaw_compose`'s concern.

## 2. Terms are the form {#data-terms}

**A value is a BEAM term, and its encodings are adapters** (dco-tek/macaw/macaw#188, macaw_data#27 to #31), as in macaw_layers ([macaw_layers 00 §2](https://github.com/dcoai/macaw_layers/blob/main/spec/00-overview.md#layers-terms)):
- **Identity is the term's.** A schema's version is the kernel's digest of its term ([01 §1.10](01-sources.md#sources-schema-version)); the operations registry and a checked step are identified the same way ([04 §2](04-operations.md#operations-registry)).
- **Validity is the term's.** A data color is a color term, never text ([01 §1.7](01-sources.md#sources-schema-colors)); a derived source is judged as the value it is ([02 §1.1](02-derived.md#derived-value)).
- **Each value has one form.** Names, states and roles are strings; a category value is held as its string. No value is kept in two spellings.
- **JSON and Arrow are adapters at the edge.** The schema's and a derived source's JSON forms are written and read at the edge ([01 §1.11](01-sources.md#sources-schema-json), [02 §1.5](02-derived.md#derived-forms)); packed columns are laid out as Arrow lays them out, and packing never changes a value ([01 §1.1](01-sources.md#sources-table)).

## 3. Dependencies {#data-dependencies}


It requires one library at runtime, **`macaw_layers`**, the document kernel: a schema's JSON is read through its gates and its version is its digest ([01 §1.10](01-sources.md#sources-schema-version), [01 §1.11](01-sources.md#sources-schema-json)). Nothing else is required, so an adopter that uses no other Macaw library (visualize, standalone) depends on `macaw_data` and `macaw_layers` alone. The rest is optional:
- **`table` and `nx`:** a host that has either gets its `Table.Reader` sources or tensors read into a table ([01 §1.1](01-sources.md#sources-table)), and **a host with neither compiles it without a warning** (CI compiles it so, #7).
- **`zigler`, a build tool only:** with it and the Zig it targets, the native kernels are built; without it, every step runs its Elixir path ([04 §1.7](04-operations.md#operations-native)).
- **`telemetry`:** a host that has it starts `Macaw.Data.Source.Telemetry`'s collector ([01 §10.3](01-sources.md#sources-telemetry)); one without it compiles the module without a warning, and the collector answers `{:error, :no_telemetry}`. CI's adopter build, which lists no optional dependency, checks both.

**Of the kernel's untrusted strings** ([macaw_layers 01 §8](https://github.com/dcoai/macaw_layers/blob/main/spec/01-kernel.md#kernel-untrusted)), macaw_data's documents hold none that needs a host's say. **They hold no URL:** a derived source's reader holds what it reads to the kernel's closed policy ([02 §1.5](02-derived.md#derived-forms)), and a schema's reader reads no `$url` ([01 §1.11](01-sources.md#sources-schema-json)), so no read takes a `urls:` policy. **It builds no theme and writes no CSS:** a data color is a color term judged by the kernel's `Color` ([01 §1.7](01-sources.md#sources-schema-colors)), so the untrusted-text checks are its adopters', where they write a schema's labels and colors into a page.

**No version is written here.** The requirements are `mix.exs`'s, and only there, so this section cannot fall behind them (#34).

**No locked dependency carries a security advisory or is retired** (macaw_data#162, dco-tek/macaw/macaw#214), outside the reasoned allowlist `ci/advisories_allowlist.exs`, empty by default. CI's `audit` job runs `ci/advisories.exs`, the Macaw family's guard, over `mix hex.audit`. An advisory the list does not name fails it, by any id the audit prints for it; so does a retired package, which has no entry and is updated, an entry the audit no longer reports, a malformed entry, and an audit that fails without a finding (Hex unreachable is no clean answer).

```test:data-dependencies-advisories
the advisory guard passes this library's lock; a seeded advisory outside the list fails at its heading, by its id or an aka; a retired package, a stale entry, a malformed one and an audit failing without a finding each fail
```

**A Hex publish is of the clean, pushed release tag** (macaw_data#162, dco-tek/macaw/macaw#190). `mix hex.publish` first runs `ci/release_guard.exs` with the version, the family's guard, as macaw, macaw_layers and macaw_component do: it refuses a working tree with changes, a HEAD that is not `vVERSION`, and a tag not on origin.

**The family's CI scripts are vendored, and a drifted copy fails** (macaw_data#162, #165). `ci/advisories.exs`, `ci/raises.exs`, `ci/release_guard.exs` and `ci/spec_links.exs` are copied byte for byte from claude-tools' `macaw_ci/`, the family's reference, because CI can't reach it. A copy drifts two ways, and each is caught where it can be seen. `ci/vendored_manifest.exs` holds each copy's SHA-256 as vendored, and CI's `vendored` job (`ci/vendored.exs`) fails on a listed copy that is missing or differs from its hash, an edit made here that belongs upstream, and on a manifest that lists none. A reference that moved on is seen only where the reference is, so `mix hex.publish` first runs `ci/vendored.exs --reference` (the reference at `$MACAW_CI_REFERENCE`, else `~/Projects/claude-tools/macaw_ci`): a family script not vendored, a vendored one the family dropped and a copy unlike the reference's each fail, and so does a reference that isn't there, never a skipped check. `ci/vendored.exs --vendor` copies the reference in and rewrites the manifest, so the manifest is never edited by hand. `ci/vendored.exs` is this library's own, not a family copy.

```test:data-dependencies-vendored
this library's copies are the ones its manifest names and the manifest lists every family script; --vendor writes copies and a manifest both checks pass; an edited copy, a missing one and an empty manifest fail in CI; at a release a reference that moved on, gained a script or dropped one fails, and an absent reference fails
```

## 4. Order of work {#data-order}

Built in the family's order of work, which puts first what adopters consume. Each step is done; what each release brought is the CHANGELOG's, and its version mix.exs's, never this spec's (macaw_data#238):
1. **the interaction event** (step 1);
2. **the data model** (step 3, macaw_compose#57);
3. **the source contract and its kit** (step 4, macaw_compose#58);
4. **derived sources** (step 5, macaw_compose#82), then **transforms, table operations and aggregates** (step 6, macaw_compose#83). A delivery keeps the rows its source gave, packing on demand, for live charts (macaw#185).
5. **the source contract as a time-varying relation, and chunked tables** (macaw_data#10, #9). A push is a numbered changelog with corrections and settled ranges ([01 §2.5](01-sources.md#sources-model), [§4](01-sources.md#sources-push)); a table is a list of immutable chunks that every step works a chunk at a time, with optional native kernels ([01 §1.1](01-sources.md#sources-table), [04 §1.4](04-operations.md#operations-steps), [§1.7](04-operations.md#operations-native)). Since then: terms are the form (§2, macaw_data#27 to #31). An application starts without the kernels with nothing logged at error level (macaw_data#76). A request has a row order ([01 §2.3](01-sources.md#sources-request), macaw_data#80). Errors are values (§5, macaw_data#114). A derived source reads its inputs as columns (macaw_data#107), and a table is finished on its columns (macaw_data#105). Every kind of time is on one instant scale (macaw_data#124, #127, #141), and a table is gathered and reduced on its columns across chunks (macaw_data#128, #132, #133, #140). A source may say its answer is stale ([01 §3](01-sources.md#sources-delivery), macaw_data#148), an inverted request window is refused (macaw_data#122), a push holder and a time column have public seams (macaw_data#123, #149), and errors as values are finished: worded `!` twins on one exception and readers of rows that answer values (§5, macaw_data#130, #161). A typed parameter may default to no value ([01 §2.2](01-sources.md#sources-parameters), macaw_data#175), and the implicit raises found in `Source.Push`, `Stack.generate/2` and `Schema.from_map/1` are faults (macaw_data#166, #178, #182). §5's promise is kept past the readers: an improper list answers its position's fault, a step's arithmetic past a float's range is `:overflow`, the readers named here all have `!` twins, and `Macaw.Data.Reduce`, `Macaw.Data.FFT` and `Macaw.Data.Source`'s dispatch answer values (macaw_data#184, #181, #185, #192, #191). A sliding `Source.Push.trim/2` reads each chunk's last value, its answers unchanged (macaw_data#201). macaw_layers' functions answer values (macaw_data#216); a native kernel's fault is a term, and `Native.elixir/1` and `normal_schedulers/1` run in a process of their own (macaw_data#101); a push holder has readers of its cache, position and last drain (macaw_data#202); a drain costs the rows an increment brings ([01 §4](01-sources.md#sources-push), macaw_data#204); and a table is digested by its contents ([01 §1.1.2](01-sources.md#sources-table-identity), macaw_data#218, #220). A ceiling budget that is no positive integer is refused ([01 §6.1](01-sources.md#sources-budgets), macaw_data#199), many rows of a table are read by index in one gather ([01 §1.1](01-sources.md#sources-table), macaw_data#205), and each row of a drain's increment is read once, for its columns, its slot and its place ([01 §1.1.4](01-sources.md#sources-table-delta), [§4](01-sources.md#sources-push), macaw_data#215). `Native.enter/1` is the public entry for a host's own counted process ([04 §1.7](04-operations.md#operations-native), macaw_data#224); `:point` and `:color` columns are packed, and a drain into a holding laid by row count joins its rows after the last chunk's ([01 §1.1](01-sources.md#sources-table), [§1.1.4](01-sources.md#sources-table-delta), macaw_data#231); and a struct `status:` beside `order:` or `values:` is the status's fault (§5, macaw_data#236).

Each is released by git tag. An adopter published on Hex (visualize) switches when `macaw_data` is published on Hex, keeping a field-identical interim definition checked against this one meanwhile.

## 5. Errors are values {#data-errors}

**A public function answers bad input with `{:error, reason}`; it does not raise** (macaw_data#114). A raise is caught by no one, because this library and its adopters rescue nothing, while a value is read by the caller that can act on it.
- **Success** is `{:ok, value}`, or a bare value only where nothing the caller passes can fail.
- **A `name!` twin** may raise. It calls `name` and raises its `{:error, reason}` as a `Macaw.Data.Error` (macaw_data#130, #157): the term itself on the exception's `reason`, exactly as the twin answers it, and its words for the message, never an `inspect`ed fault. A module with words of its own (`format_error/1`) words its reasons, and every other reason is worded by the library's one formatter, `Macaw.Data.Fault.sentence/2`. The terms are on the exception and not only in the message, so a reader of a crash report or a test reads them without parsing words. An `ArgumentError` has no field to carry them. The twin is for a caller that knows its input is valid, as the library's own callers often do.
- **A macro's misuse** fails the build with a `CompileError`: there is no caller to answer.
- **A broken internal invariant** may raise. That is a bug in this library, not bad input, and each one is named in the guard's allowlist with its reason.
- **An argument of the wrong type is out of scope** (macaw_data#130). A `FunctionClauseError` from a guard on a public function's argument type, a map where a list is taken, is a programming error, not input a document, a viewer or a source controls. An argument of the right type but the wrong shape, a list of the wrong elements, is input, and answers a fault.

**Reasons are data, in one vocabulary,** the shapes the library already answers:
- a fault at a place, `{path, reason}`: a list of the keys, indexes and names that lead to the bad part, and why (`Table.from/1`, `Schema.new/1`, `Operations.apply/4`, a derived source's form, [01 §1.1](01-sources.md#sources-table), [04 §3.1](04-operations.md#operations-run));
- a reason about a value read, `{:unknown_column, name}`, `{:wrong_type, name, expected, actual}` and `{:type, what}` ([02 §2.2](02-derived.md#derived-input-windows));
- a module's own named reasons, such as a unit's `{:dimension, from, to}` ([03](03-units.md)).

Each module's `format_error/1` gives a reason's words, and each converted function's spec section names its reasons.

```test:data-errors-twins
every ! twin raises Macaw.Data.Error whose reason is exactly its value twin's error term and whose message is words with no inspected fault; the formatter words a fault list by path, a bare reason, a module's own reason through words:, and an unknown reason as its term
```

**The guard**, `ci/raises.exs`, holds the library to this. It is the Macaw family's guard, vendored byte for byte from `claude-tools/macaw_ci/raises.exs` and held to that copy as the family's other CI scripts are, in CI and before a release ([§3](#data-dependencies), macaw_data#130, #160, #165; macaw#243, #247). It reads every `.ex` file under `lib/` as code, so a raise in a doc or a comment is no site. It finds each `raise`, `reraise`, `throw` and `exit`, their `Kernel.` and `:erlang.` forms, and `Mix.raise`, each with the function it is written in, `{Module, name, arity}`, or the module body, `{Module, nil, nil}`. Every site's function must be named in `ci/raises_allowlist.exs`, `%{at: {Module, name, arity}, class: class, reason: words}`, and the guard verifies the class:
- `:bang`: a `!` twin. Its name ends in `!` and its module defines the twin of the same name without it, at the same arity. Each twin raises its own `Macaw.Data.Error`; no helper raises for it.
- `:compile`: a macro, or a module body, refusing bad code while the caller compiles. A raise in the code a macro generates runs in the caller and is refused.
- `:mix_task`: a Mix task's failure (this library has none).
- `:invariant`: a case no input can reach, kept with the reason it can't.

A site outside the list fails, and so does an entry whose class doesn't hold, an entry that matches no raise, a malformed entry and a file that doesn't parse. Bad input has no class.

```test:data-errors-guard
the vendored raise guard passes this library and its allowlist; a raise, a throw or an exit outside the list fails at its line, a raise in a doc is no site; a listed twin passes, while a :bang entry without its twin, an entry that matches no raise and a :compile entry on a def fail
```

**What once raised implicitly answers too** (macaw_data#121). A function's option it does not take is `{[key], :unknown_key}` and a missing required one `{[key], :required}`, where `Keyword.validate!/2` and `Keyword.fetch!/2` would raise; a quantity not in `Macaw.Data.Quantity.all/0` is `{:unknown_quantity, quantity}`, a system none of `systems/0` `{:unknown_system, system}` and a metric kind none of `:gauge`, `:counter` and `:rate` `{:unknown_metric_kind, kind}`, where a map read would raise. What stays an implicit raise reads only what the library itself built: an engine's map by a path it defined, a chunk's column by its header's name, a word table by a word the checker produced. macaw_layers answers values too (0.5.0): its digest of a term that is not data, a reader's options that are none, a URL policy or limits it can't build, each a fault. A caller's term that reaches the digest is judged first, so it is a fault here too (`Operations.step_digest/2`'s node, `Step.parts/4`'s, a table's origin); the kernel's digest of a term this library built (a chunk's derivation and combined id, a step's identity over a checked node, a registry's names, a schema's fields) is a named invariant, and a `!` twin of the kernel is called only on configuration written in code (`Url.Policy.new!([])`). **`Macaw.Data.Table.rows/1` answers a source `Table.source/1` refuses with its faults** (macaw_data#130, #158), as `Delivery.rows/1` does under `[:rows]`, each with a `rows!/1` twin, so reading rows is no named invariant. An aggregate's `reduce/2` and `step/3` take readings as its `reads/0` declares, checked by `Operations.aggregate/4` and the steps: those two are named invariants in the guard's allowlist.

**No reader of untrusted input raises** (macaw_data#130, #159). This is proven by properties over generated malformed input of the type each reader takes, run over 40 seeds before a release. The readers are `Table.new/2`, `Table.from/2`, `Schema.new/1`, `Schema.from_map/1`, `Schema.from_json/2`, `Source.Description.new/1`, `Source.Request.new/1`, `Derived.new/1`, `Derived.from_map/2`, `Source.Push.new/3`, `Source.Finish.ceiling/2` and `Table.rows_at/2` (macaw_data#205), besides `Delivery.new/2` and `Operations.apply/4` (#114), and the readers of a caller's source besides `from/2`: `Table.column_types/1`, `Table.time_columns/1` and `Stack.generate/2` (macaw_data#161), and the engines a caller may call directly: `Stack.stacked/2`, `Reduce.lttb/3`, `Reduce.m4/3`, `FFT.fft/1`, `FFT.spectrum/3`, `FFT.magnitudes/1` and `FFT.window/2` (macaw_data#192), and the readers of a format: `Format.parse/2`, `Format.parse_time/2`, `Format.for_measure/2` and `Format.Locale.new/1` (macaw_data#251), and the shipped sources' constructors: `Source.Signal.new/3`, `Source.Combined.new/2` and `Source.Telemetry.start_link/1` (macaw_data#250, #249). Each answers `{:ok, value}` or `{:error, faults}`, and its `!` twin raises exactly those faults. **A list has a shape, and its tail is part of it** (macaw_data#184, #169). `is_list/1` passes an improper list, `[1 | 2]`, and `Enum` raises on it, so a reader judges a list a caller gave with one guard, and an improper list is the fault that position has for any other wrong list: `{[:order], {:type, :order}}`, `{[name, :values], {:type, :values}}`, `{[], {:type, :source}}`. Where a position took only a list, it has its own: `{[], {:type, :columns}}` from `Table.new/2`, `{["nodes"], {:type, :nodes}}` from `Operations.validate/3` and `apply/4`. `Delivery.new/2` does not walk a list of rows, as it reads no row: an improper one is `Table.rows/1`'s fault when it is read. A value a step takes as any term is data, since the step's identity is its digest: `{[i, key], {:type, :term}}` for a function, a PID, a reference, a port or an improper list. A map form holding a struct or an improper list is the kernel's to refuse (macaw_layers#37). Until that lands, `Derived.from_map/2`'s property generates document terms only.

**A `!` twin that reads rows is called only where its argument can't be refused** (macaw_data#161). The raise guard reads literal raise sites, so a function without `!` that hands a caller's source to `Table.rows!/1`, `Delivery.rows!/1` or `Delivery.named_rows!/1` raises unseen. A test lists every such call in `lib/` with why its argument always answers (a table, a delivery `Delivery.new/2` checked), and fails on a call it does not list and on a listed call that is gone. `Source.Push` reads a snapshot's and an increment's rows through `Delivery.named_rows/1` and records its faults ([01 §4](01-sources.md#sources-push), macaw_data#166), so it has no such call for a delivery's rows.
